# /sponsors – the sponsor list in the README

The maintainer is Yannic Schuller (GitHub `yannicschuller`). Talk to him in **German**. Repository: `/home/user/flowplan` (`yannicschuller/flowplan`).

He gives the sponsors in the message, one per line, for example:

```
@octocat – Champion ($25) – seit 2026-11 – öffentlich
Firma X – Organisation ($100) – Logo: https://example.com/logo.svg – Link: https://example.com
@someone – Supporter ($3) – seit 2026-10 – anonym
@octocat jetzt Backer
@octocat raus
```

## Privacy first

The repository is public: **everything in `sponsors.json` and the README is public.** So:

- **No amounts.** Store and show only the tier, never a dollar amount, a sum or a "since" duration in money. The amounts in his message only identify the tier and are dropped.
- **No name without consent.** A sponsor not marked public (`öffentlich`, `public`, `sichtbar`) is anonymous: in `sponsors.json` only as `{ "tier", "since", "visible": false }` – no name, handle, link or logo. If the consent is unclear, ask; never assume "public".
- **No personal data** beyond what he gives explicitly for this purpose (name or handle, link, logo URL). Never e-mail addresses, real names behind a handle, locations, amounts. A field that looks like an e-mail address is refused, with a note.
- **Logos only as links** (https URLs, shown as `<img src=…>`), never downloaded into the repository – unless he says so explicitly.

## sponsors.json

At the repository root. Create it on the first run (empty `sponsors` list). Format:

```json
{
  "$comment": "Maintained with /sponsors (.claude/skills/sponsors/SKILL.md). Public: only tiers, never amounts; anonymous sponsors without names.",
  "tiers": ["organisation", "champion", "backer", "supporter"],
  "sponsors": [
    { "name": "Firma X", "tier": "organisation", "link": "https://example.com", "logo": "https://example.com/logo.svg", "since": "2026-11", "visible": true },
    { "github": "octocat", "tier": "champion", "since": "2026-11", "visible": true },
    { "tier": "supporter", "since": "2026-10", "visible": false }
  ]
}
```

- `github`: the handle without `@` (letters, digits, single hyphens, max. 39 characters) – for GitHub accounts; `name` (+ optional `link`) for everyone else. One of the two, for visible sponsors only.
- `tier`: `organisation` ($100), `champion` ($25), `backer`, `supporter` ($3) – matched case-insensitively from his words (Organisation/Organization/Firma, Champion, Backer, Supporter). An unknown tier name or amount → ask which tier it is; don't guess.
- `since`: `YYYY-MM` as he gives it; if missing, the current month. Only used for the order (longest first) – never shown.
- `link`, `logo`: `https://` only.
- Keep the file sorted: tier order, then `since`, then name. 2-space indentation, trailing newline.

## Commands in his message

- **New line with a tier** → add, or update the existing entry with the same handle/name (tier, link, logo, visibility, since).
- **Tier change** ("@octocat jetzt Backer", "Firma X → Champion", or a new line for a known sponsor) → change only the tier; keep `since`.
- **Removal** ("@octocat raus", "Firma X entfernen", "@x hat beendet") → delete the entry.
- **Anonymous sponsors** have no name to refer to: "ein anonymer Supporter weniger", "anonymer Backer → Champion" changes one entry of that tier (the newest by `since`, say which one).
- **Public ↔ anonymous**: going anonymous deletes name, handle, link and logo from the entry; going public needs the name/handle again.
- Anything unclear (two sponsors with the same name, a removal of someone not in the list) → ask before changing.

Then summarise the change in one short German list (added / tier changed / removed / anonymous count).

## The README section

The block in `README.md` between the markers – nothing outside them is touched:

```
<!-- sponsors:start -->
…generated…
<!-- sponsors:end -->
```

If the markers don't exist yet, insert them once in the section `## Support Flowplan`, right after its paragraph, and say so. Generate the block from `sponsors.json`, always completely (never edit by hand inside it):

```markdown
<!-- sponsors:start -->
<!-- Generated by /sponsors from sponsors.json – edits here are overwritten. -->
### Sponsors

**Organisations**

<a href="https://example.com"><img src="https://example.com/logo.svg" alt="Firma X" height="48"></a>

**Champions**

<a href="https://github.com/octocat"><img src="https://github.com/octocat.png?size=96" alt="@octocat" title="@octocat" width="48" height="48"></a>

**Backers**

…

Thank you also to our supporters: @alice, @bob – and 3 more who prefer not to be named.

[♥ Become a sponsor](https://github.com/sponsors/yannicschuller)
<!-- sponsors:end -->
```

- **Organisations** (top): logo linked to `link` (`height="48"`, `alt` = name); without a logo the name as a link (or plain text without a link).
- **Champions, then Backers**: GitHub avatars (`https://github.com/<handle>.png?size=96`, 48×48, linked to the profile, `alt`/`title` `@handle`); sponsors without a GitHub account as name links. Avatars of a tier in one paragraph, separated by a space.
- **Supporters**: one thank-you line with the public handles as `@handle` (GitHub links) or names.
- **Anonymous** sponsors of every tier: only counted, in that thank-you line ("– and N more who prefer not to be named"); if there are no public supporters: "Thank you also to N sponsors who prefer not to be named." Never per-tier counts of anonymous sponsors and never amounts.
- Empty tiers are left out completely. With no sponsors at all, the block is just a short invitation ("Flowplan has no sponsors yet – you could be the first.") and the link.
- Always last: `[♥ Become a sponsor](https://github.com/sponsors/yannicschuller)`.
- English, as the README. No dates, no amounts, no tier prices.

## Preview, OK, ship

1. Show him the change summary and the **new block** – rendered as Markdown (not in a code block) and below it the raw Markdown in a code block – plus the `sponsors.json` diff.
2. **Wait for his OK.** Changes → apply, show again. Nothing is committed before the OK.
3. Then commit `sponsors.json` and `README.md` with the subject `Sponsors: <short summary>` (e.g. `Sponsors: add @octocat (Champion), remove Firma X`) and the trailers from CLAUDE.md plus the attribution lines the session's system prompt gives. Push like `/ship`: `git push -q origin HEAD:main`, then `git push -q -f origin HEAD:<session branch>`. Only README and sponsors.json changed: no beta build needed; check that CI on the commit is green.
